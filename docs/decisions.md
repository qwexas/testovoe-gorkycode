# Восстановленные решения «Горького»

[README и запуск](../README.md).

Оригинального документа ответов Q1–Q38 в репозитории нет. Этот перечень **восстановлен по комментариям и текущему коду**, а не является исторической стенограммой. Идентификаторы сохранены для прослеживаемости. «Обоснование» ниже объясняет устройство реализации; оно не приписывает автору неизвестные мотивы. Изменения M1 явно отделены от восстановленной истории.

Найдены ссылки на Q5, Q8, Q9, Q11, Q13, Q20, Q21, Q22, Q23, Q24, Q26, Q27, Q30–Q38. Q1–Q4, Q6–Q7, Q10, Q12, Q14–Q19, Q25, Q28–Q29 **не восстановлены**. Строки `Q3` в тестах озвучивания и похожие подстроки в lock-файле не считаются ссылками на продуктовые решения.

## Q5 — распознавание речи

- Поведение: faster-whisper на CPU с int8 и VAD, русская речь, аудио приводится к моно 16 кГц.
- Обоснование: единая граница `SpeechToText` отделяет распознавание от диалога и позволяет тестировать без модели.
- Последствия: работа зависит от доступности весов и CPU; пустая речь приводит к `speech_not_recognized`, ошибка модели — к `stt_unavailable`.
- Код: [whisper.py](../backend/app/voice/whisper.py), [audio.py](../backend/app/voice/audio.py), [interfaces.py](../backend/app/voice/interfaces.py).

## Q8 — интерфейс «Консоль»

- Поведение: сфера голоса, лог сессии, план дня, статусная строка; на телефоне — вкладки. Моноширинная гарнитура Martian Mono и общие дизайн-токены.
- Обоснование: общий набор терминальных примитивов делает части экрана согласованными.
- Последствия: требуется отдельное управление фокусом, клавиатурой и поведением узкого экрана.
- Код: [console-screen.tsx](../frontend/src/features/console/components/console-screen.tsx), [tty.css](../frontend/src/components/ui/tty.css), [layout.tsx](../frontend/src/app/layout.tsx).

## Q9 — язык и часовой пояс

- Поведение: русский язык и `Europe/Moscow`; API нормализует время, календарь публикует TZID.
- Обоснование: одна временная модель связывает NLU, план дня и календарь.
- Последствия: пользовательская смена пояса не реализована; локальный пояс браузера не меняет смысл дат.
- Код: [schedule.py](../backend/app/core/schedule.py), [format.ts](../frontend/src/lib/format.ts), [calendar.py](../backend/app/core/calendar.py).

## Q11 — анонимный профиль; текущая редакция после M1

- Поведение: существующая сессия проверяется по HttpOnly cookie, в БД хэш токена и HMAC кода восстановления. Создание **только** через явный защищённый POST `/api/profiles`. GET `/api/me` и остальные защищённые операции без сессии возвращают 401. Восстановление не создаёт промежуточный профиль. DELETE без сессии идемпотентен.
- Обоснование текущей правки: чтение не должно создавать данные и расходовать ресурс создания, а одноразовый код обязан попасть в ответ создания. Ограничение частоты создания сохранено.
- Последствия: первый вход требует действия пользователя, frontend/backend обновляются согласованно. Код надо сохранить; сервер не может повторно показать исходный код. Фоновый 401 переводит UI в состояние без сессии и блокирует запросы профиля. При другом ID прежний код очищается; GET того же ID не закрывает ещё открытый код.
- Код: [profiles.py](../backend/app/core/profiles.py), [dependencies.py](../backend/app/api/dependencies.py), [routes/profiles.py](../backend/app/api/routes/profiles.py), [profile-state.ts](../frontend/src/features/profile/profile-state.ts), [profile-session.ts](../frontend/src/lib/api/profile-session.ts).

## Q13 — синтез ответа

- Поведение: Silero v4_ru на CPU, нормализация чисел/латиницы перед синтезом, OGG/Opus; frontend имеет браузерный fallback.
- Обоснование: серверная озвучка даёт единый голос, fallback снижает зависимость воспроизведения от формата и сервера.
- Последствия: синтез требует весов/ресурсов; браузерный голос зависит от устройства и разрешений. В исходном [комментарии Silero](../backend/app/voice/silero.py) указана CC BY-NC-SA 4.0; условия версии необходимо проверять у [поставщика](https://github.com/snakers4/silero-models), права на проект/сторонние модели этот документ не предоставляет.
- Код: [silero.py](../backend/app/voice/silero.py), [text_normalizer.py](../backend/app/voice/text_normalizer.py), [use-speech.ts](../frontend/src/features/voice/hooks/use-speech.ts).

## Q20 — вычисление речи на CPU

- Поведение: STT исполняется на CPU. Комментарий кода фиксирует ограничение CTranslate2 для указанной серверной GTX 960 и выбор по замерам; серверный пример использует `medium`, общий пример — `large-v3-turbo`.
- Обоснование: конфигурация позволяет выбирать скорость/качество под железо; приведённые в комментариях замеры не являются гарантией для другой машины.
- Последствия: латентность и параллелизм зависят от CPU, длины фразы и очереди.
- Код: [whisper.py](../backend/app/voice/whisper.py), [voice/settings.py](../backend/app/voice/settings.py), [серверный пример](../infra/deploy/env.production.example).

## Q21 — единый origin и прокси

- Поведение: Next.js проксирует `/api` при локальной работе/Compose; nginx в серверном примере направляет API прямо в FastAPI. Порты Compose привязаны к loopback.
- Обоснование: браузер обращается к API своего origin без широкого CORS.
- Последствия M1: Origin создания задаётся явным списком; схема доверия не выводится из forwarded-заголовков. При смене адреса надо обновить список; при смене backend rewrites Next.js надо пересобрать.
- Код: [next.config.ts](../frontend/next.config.ts), [nginx](../infra/nginx/voice.wexasas.online.conf), [profile_creation.py](../backend/app/api/profile_creation.py).

## Q22 — история нового профиля

- Поведение: 1000 исходных записей материализуются только при явном создании профиля; общая таблица seed хранит индексы, собственные записи ссылаются на неё до изменения названия. При старте готовится общая заготовка. Восстановление историю не копирует.
- Обоснование: общие индексы позволяют не вычислять векторы заново для каждого профиля.
- Последствия: создание всё ещё пишет 1000 строк; статусы импорта зависят от момента создания. Оптимизация seed, ретеншн и очистка доказанных сирот — отдельные задачи, старые данные автоматически не удаляются.
- Код: [history.py](../backend/app/core/history.py), [repositories.py](../backend/app/storage/repositories.py), [build_seed.py](../backend/scripts/build_seed.py).

## Q23 — состояние разговора

- Поведение: сохраняются отложенный вопрос, фокус записей, группа последнего списка и последние реплики. Фокус ограничен десятью ID, контекст — шестью репликами.
- Обоснование: местоимения и уточняющие ответы требуют памяти между HTTP-запросами.
- Последствия: явные ограничения цели должны применяться и к фокусу; несколько равноправных записей требуют выбора.

## Q24 — разделение извлечения и действия

- Поведение: LLM извлекает поля; даты, изменение данных и текст ответа определяет код. Ответы пользователю — шаблоны.
- Обоснование: правила можно проверять без сети и генерации свободного текста.
- Последствия: ошибка извлечения остаётся возможной; корректность бизнес-логики не доказывает качество настоящей модели.

## Q26 — запись и управление голосом

## Q27 — календарь

- Поведение: скачивание `.ics` требует сессии; подписка по секретному токену работает без cookie, с отдельным лимитом. Экспортируются открытые записи с датой от текущего дня.
- Обоснование: календарные клиенты не могут полагаться на cookie браузера.
- Последствия: ссылка является доступом; её нельзя публиковать. Перевыпуск токена пока не реализован; работа `webcal://` и обновление зависят от клиента.
- Код: [routes/calendar.py](../backend/app/api/routes/calendar.py), [core/calendar.py](../backend/app/core/calendar.py), [calendar-subscription-dialog.tsx](../frontend/src/features/profile/components/calendar-subscription-dialog.tsx).

## Q30 — недостающие поля и уточнения

- Поведение: задача допускает отсутствие даты, напоминанию нужны дата/время, встрече — дата/время и длительность по умолчанию. Недостающие значения уточняются в диалоге.
- Обоснование: обязательность зависит от типа записи, а не только от синтаксиса команды.
- Последствия: незавершённая команда хранится как pending; API CRUD также проверяет обязательность времени.
- Код: [rules.py](../backend/app/core/dialog/rules.py), [schedule.py](../backend/app/core/schedule.py), [creation.py](../backend/app/core/dialog/creation.py).

## Q31 — правила времени

- Поведение: «утром» — 09:00, «днём» — 13:00, «вечером» — 19:00; разговорные часы 1–7 без уточнения сдвигаются на 12 часов. Явный ведущий ноль сохраняется только у времени, не у частей даты. Относительные минуты округляются вверх до пяти минут. День недели зависит от назначения (новая дата/поиск); периоды полуоткрытые. Невалидные даты и чрезмерные смещения отклоняются.
- Обоснование: вычисления централизованы и не возложены на LLM.
- Последствия: правила являются продуктовым допущением; одного «в шесть» недостаточно для 06:00. Предусмотрено уточнение; недопустимая дата не считается отсутствующей.
- Код: [time_resolution.py](../backend/app/nlu/time_resolution.py), [rules.py](../backend/app/core/dialog/rules.py), [тесты времени](../backend/tests/unit/nlu/test_time_resolution.py).

## Q32 — уведомления в открытой вкладке

- Поведение: браузерные напоминания и звук, пока приложение открыто; выбор разрешения пользователем.
- Обоснование: уведомление выполняется самим клиентом без серверного push.
- Последствия: закрытая/усыплённая вкладка и ограничения ОС не дают гарантии доставки; календарь — отдельный механизм.

## Q33 — подтверждение и отмена

- Поведение: удаление требует подтверждения, несколько кандидатов дают выбор; прочие изменения возвращают undo. UI показывает кнопку 10 с, сервер принимает отмену 30 с.
- Обоснование: короткое окно исправляет ошибочное действие, разница времён оставляет запас на сеть.
- Последствия: истёкшая/чужая/повторная отмена недоступна; это не полноценная история версий и не решение конфликтов параллельных изменений.
- Код: [changes.py](../backend/app/core/dialog/changes.py), [undo.py](../backend/app/core/dialog/undo.py), [undo-control.tsx](../frontend/src/features/assistant/components/undo-control.tsx).

## Q34 — форматы записи

- Поведение: выбирается поддерживаемый браузером формат (webm/opus, ogg, mp4/aac); сервер потоково ограничивает размер и декодирует поддерживаемые контейнеры через PyAV.
- Обоснование: браузеры различаются по MediaRecorder и кодекам.
- Последствия: MIME-заголовка недостаточно, проверяется и декодирование; предел — 10 МБ/60 с с допуском кодека.

## Q35 — хранение и удаление

- Поведение: аудио обрабатывается в памяти, в истории остаётся распознанный текст. Удаление профиля каскадно удаляет его данные, frontend переспрашивает.
- Обоснование: запись аудио не нужна для последующего диалога; явное удаление должно прекращать доступ со всех сессий.
- Последствия: нет возможности повторно прослушать исходную запись; каскад не равен политике ретеншна. M1 не удаляет старые профили по неактивности.
- Код: [speech.py](../backend/app/core/speech.py), [profiles.py](../backend/app/core/profiles.py), [models.py](../backend/app/storage/models.py), [delete-data-dialog.tsx](../frontend/src/features/profile/components/delete-data-dialog.tsx).

## M1 — дополнительная граница браузерного создания

Явный POST сам по себе не защищает от HTML-форм и межсайтового вызова, а запрет чтения ответа через CORS не запрещает выполнение простого запроса. Поэтому POST создания требует `X-Gorky-Client: web`, проверяет присланный Origin по явной настройке, запрещает `Origin: null` и `Sec-Fetch-Site: cross-site`. Чужой origin не получает разрешения CORS/preflight; защита не использует клиентские Host/forwarded-заголовки как источник доверия. Проверки идут до создания/seed/commit.

Это браузерная граница, не доказательство человечности клиента. Прямой HTTP-клиент способен прислать такой заголовок; лимит создания сохранён. Общая защита от ботов, оптимизация seed, ретеншн и согласованная очистка исторических сирот остаются отдельными задачами. Остальные находки ревью этим документом не объявляются исправленными.

Код: [profile_creation.py](../backend/app/api/profile_creation.py), [config.py](../backend/app/config.py), [тесты жизненного цикла](../backend/tests/integration/test_profile_lifecycle.py). Настройка и команды — в [README](../README.md).
